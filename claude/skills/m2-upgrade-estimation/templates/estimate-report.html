Supuestos y límites

Leer antes de citar estos números:
  • ±30% ROM. Estas cifras son estimaciones de Rough Order of Magnitude, no compromisos. Usarlas para presupuestar, no para prometer fechas.
  • Equipo asumido: 1 dev + 1 QA dedicados. Escalar el equipo no escala el tiempo en forma lineal (ley de Brooks).
  • El track "con automatización" asume cobertura medida de Rector, UCT y phpcs sobre este código específico. Herramientas no instaladas o reglas que no aplican reducen el ahorro real.
  • Excluye: approvals de stakeholders, ventanas de change-management, monitoreo post-deploy y descubrimiento de regresión (bugs que QA manda de vuelta al dev son una iteración aparte).
  • Excluye: integraciones externas (ERP, CRM, analytics, certificaciones de medios de pago de terceros) que requieran re-verificación post-upgrade.
Cómo leer PERT vs ROM: PERT da una distribución, no un número. Para comprometer una fecha con 90% de probabilidad usá el CI 90%; para una fecha agresiva (más riesgo) el CI 70%. El E es el promedio matemático, útil para presupuestar pero no para prometer.
